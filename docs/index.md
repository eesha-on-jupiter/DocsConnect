# DocsConnect

DocsConnect is a Grasshopper plugin for Rhino 7/8 (Windows and Mac) that wraps the
[Google Docs API](https://developers.google.com/docs/api/reference/rest) v1, plus a small slice of
the Google Drive API (`files.list`) for resolving a document by name. It lets you author, populate,
and restructure Google Docs entirely from a Grasshopper canvas — build a request in JSON-emitting
components, stack and sequence those requests, then push them to a live document in one
`batchUpdate` call.

- **Platform:** Google Docs API v1 (`https://docs.googleapis.com`)
- **Auth:** OAuth 2.0, Bearer token (you supply a token; the plugin does not run its own OAuth flow)
- **Version:** 1.0.0 (pre-release)
- **Made with:** the [PleaseREST](https://github.com/eesha-on-jupiter/PleaseREST) Claude Code plugin — DocsConnect was generated by its API-to-Grasshopper pipeline
- **Rhino support:** Rhino 7 (.NET Framework 4.8), Rhino 8 Windows (.NET 7), Rhino 8 Mac (.NET 7)

## Features

- **Self-indexed authoring** — Text, Paragraph, and most Insert components author their own request
  at a placeholder position, so there's no manual index bookkeeping. [Request Aggregator](components/Combine/RequestAggregator.md)
  resolves everything to real document positions right before the batch fires.
- **Atomic and composite style components** — single-trait toggles (Bold, Italic, Font Size, Heading
  Level, and more) for fine-grained control, plus composite report helpers ([Report Skeleton](components/Paragraph/ReportSkeleton.md),
  [Report Header Block](components/Paragraph/ReportHeaderBlock.md), [Bullet List](components/Paragraph/BulletList.md))
  for assembling common report structures in one drop.
- **Chainable styles** — every Text- and Paragraph-tab styling component takes an optional
  Request JSON input. Wire one component's output into the next and its trait is added to the same
  text rather than inserting a second copy, so a heading can also be colored, centered and spaced by
  stacking components one at a time. See [chaining.md](chaining.md).
- **Segment targeting** — any Text- or Paragraph-tab component can target a header, footer, or
  footnote instead of the document body via an optional Segment ID input.
- **Image pipeline** — capture one or many Rhino viewports, host them (or any local files/bitmaps)
  on Drive, and insert them inline one per line, all from Grasshopper. See [Insert tab](components/Insert/index.md).
- **Data-driven tables** — populate a table directly from a Grasshopper data tree, either
  size-inferred ([Data Tree To Table](components/Table/DataTreeToTable.md), with a `Transpose` for
  column-wise data) or with explicit row/column counts ([Fixed Size Table](components/Table/FixedSizeTable.md)).
  Per-cell formatting comes either as matching value trees (bold, italic, underline, font, text
  colour, cell fill) or by wiring a style component's coloured output straight into the data.
- **Document-wide style control** — margins, page size, and background color via a single JSON
  component ([Update Document Style](components/Document/UpdateDocumentStyleJson.md)).
- **Document lookup by name** — resolve a Document ID from a title via the Drive API instead of
  hardcoding IDs (see [Get Document](components/Document/GetDocument.md)).
- **Curated presets** — value-list shortcuts for named styles, bullet glyphs, alignment, and font
  family, so you're not guessing at Google's enum strings. See [Presets tab](components/Presets/index.md).
- **Safety by design** — every write operation (create, batch update, clear, header/footer/footnote
  creation, image hosting) only fires on a literal button click, never on canvas recompute.

## Install

Install via the Rhino Package Manager (`PackageManager` command in Rhino) and search for
**DocsConnect**, or drop the `.gha` for your platform into your Grasshopper
`Libraries` folder and restart Rhino. See [authentication.md](authentication.md) for how to get a
token before your first live call.

## The two families of components

**HTTP components** (Connect tab, and most of Document tab) make a live network call — they need a
Token and, for most, a Document ID. Write operations (Create Document, Batch Update, Clear Document,
Create Header/Footer/Footnote) are `ButtonComponent`s: they only fire on a literal mouse-click on the
component, never on canvas recompute, so a live document is never modified by accident while you're
still wiring things up. Create Footnote goes one step further: since it appends at the end of the
document rather than taking a raw index, it reads the document first (an internal Get Document call)
to find the current end of the body before writing.

**JSON components** (Text, Paragraph, Insert, Table, Combine, Presets tabs, plus Update Document
Style in the Document tab) never touch the network. They emit a `Request JSON` string (or list)
describing one Google Docs API request object. Nearly every one is **self-contained**: it authors its
own request(s) at a placeholder position and has no index input at all — this now includes the
Insert tab (Insert Image, Insert Page Break, Insert Section Break), not just Text/Paragraph/Table.
Getting a real position happens only in [Request Aggregator](components/Combine/RequestAggregator.md):
wire every one of these blocks straight into its Request JSON input, one wire per block, in the
order they should appear (or several through one Merge), and it re-indexes them from Start Index
before handing one Requests JSON array to [Batch Update](components/Document/BatchUpdateDocument.md).
Every placed block is reset to plain Normal text on insertion before its own styling applies, so
nothing inherits formatting from the paragraph it lands in; a block that skips the aggregator is
caught with an error or warning rather than landing at the top of the document.

Text- and Paragraph-tab styling components additionally accept an optional Request JSON *input*.
Connected, they stop authoring their own text and append their trait to the incoming block instead —
zero-length requests that leave every downstream position untouched, so a chained block still passes
through Request Aggregator as a single unit. See [chaining.md](chaining.md).

Replace Image is the one exception: it targets an already-inserted image by object ID rather than a
document position, so there's nothing to place — it goes into Request Aggregator's Fixed Requests
input, which passes it through untouched. There is no
Insert Table component or named-range support: Google doesn't publish an index-delta formula for a
table's structural growth (so it can't be reliably auto-sequenced), and named ranges require real
indices into already-placed content rather than a position to insert at — neither fits this
self-indexed model. Build a table from data instead, via
[Data Tree To Table / Fixed Size Table](components/Table/index.md), which compute their own verified
cell-offset math internally.

## User workflows

A few common ways people put these components together — each drawn as a component chain in [workflows.md](workflows.md):

- **First document, first content.** Create a document, drop in a couple of Text/Paragraph blocks,
  sequence them through Request Aggregator, and push it live. The minimal version of every other
  workflow below. See [quickstart.md](quickstart.md).
- **Report from a Grasshopper run.** Build the title/heading/body scaffold with
  [Report Skeleton](components/Paragraph/ReportSkeleton.md), capture a geometry study from the
  Rhino viewport and insert it inline, then place text and image together through Request
  Aggregator before pushing to a new document. See [examples/twist-taper-tower-report.md](examples/twist-taper-tower-report.md)
  for the full worked version.
- **Structured document with running headers/footers.** Create a document, then
  [Create Header](components/Document/CreateHeaderJson.md) / [Create Footer](components/Document/CreateFooterJson.md)
  / [Create Footnote](components/Document/CreateFootnoteJson.md) to get a segment ID, and target
  that ID from any Text/Paragraph component's Segment ID input to layer in richer content
  afterward — bold, multiple lines, alignment.
- **Tabular data report.** Feed a Grasshopper data tree into [Data Tree To Table](components/Table/DataTreeToTable.md)
  (size-inferred) or [Fixed Size Table](components/Table/FixedSizeTable.md) (explicit rows ×
  columns) to turn analysis results into a populated table in one step.
- **Rebuild an existing document from scratch.** [Clear Document](components/Document/ClearDocument.md)
  wipes all content in one press, then the same self-indexed authoring pipeline as any new
  document — Text/Paragraph/Insert blocks through Request Aggregator — rebuilds
  it from a clean slate. Useful for a document that's regenerated every time a Grasshopper
  definition reruns.
- **Building up one styled block.** Chain a Text/Paragraph component's Request JSON into the next
  one to layer traits onto the same text — Heading Text into Text Color into Aligned Text gives one
  colored, centered heading instead of three paragraphs. Works on composites too (a font family
  chained onto Report Skeleton restyles every paragraph it built). See [chaining.md](chaining.md).
- **Document-wide formatting pass.** [Update Document Style](components/Document/UpdateDocumentStyleJson.md)
  sets margins, page size, and background in one request — goes into Request Aggregator's Fixed Requests since
  it has no document position to sequence.
